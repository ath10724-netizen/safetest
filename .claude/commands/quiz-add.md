# 새 문항 추가

인수: `$ARGUMENTS`

위 인수를 공백으로 나눠 **순서대로** 과목, 회차, 난이도, 문항 수로 해석한다. (번호 인수 `$1`~`$4`는 환경에 따라 한 칸씩 밀려 들어가므로 쓰지 않는다.)

`data/questions.json`에 위 조건의 새 문항을 기존 문항과 같은 형식으로 추가한다. 아래 **검증 가이드라인을 모두 통과한 문항만** 추가한다. 하나라도 통과하지 못하면 그 문항은 추가하지 않고 이유를 보고한다.

## 1. 인수 해석

인수는 공백으로 나뉘므로 띄어쓰기가 있는 값은 아래 규칙으로 정규화한다. 해석할 수 없거나 빠진 인수가 있으면 **추가하지 말고** 사용법을 알려준 뒤 멈춘다.

| 인수 | 허용 값 | 정규화 결과 |
|---|---|---|
| 과목 | `1`~`6`, 또는 과목명 일부(`산업재해`, `인간공학`, `기계`, `전기`, `화학`, `건설`) | `core/config.py`의 `SUBJECTS` 중 하나 |
| 회차 | 숫자(`3`) 또는 `모의3회`, `모의 3회` | `"모의 N회"` (기존 표기와 동일하게 띄어쓰기 포함) |
| 난이도 | `하`, `중`, `상` | 그대로 |
| 문항 수 | 1~10 정수 | 10을 넘으면 나눠서 실행하도록 안내하고 멈춘다 |

사용 예: `/quiz-add 5 3 상 2` → 화학설비 안전관리, 모의 3회, 난이도 상, 2문항

## 2. 시작 전 확인

1. `core/config.py`의 `SUBJECTS`와 `DIFFICULTIES`를 읽는다.
2. `data/questions.json`에서 해당 과목의 기존 문항을 모두 읽는다. 단원, 다룬 개념, 정답 수치, 다음 ID 번호를 파악한다.
3. `data/laws.json`에서 해당 과목 단원의 조항을 읽는다.
4. `REVIEW.md` 4.3장과 9장(법령 확인 결과)을 읽고, 개정되었거나 근거가 없다고 판정된 내용을 피한다.

## 3. 문항 형식

기존 문항과 **필드 이름·순서·자료형을 똑같이** 맞춘다.

```json
{
  "id": "S5-R3-10",
  "subject": "화학설비 안전관리",
  "unit": "폭발과 연소 이론",
  "round": "모의 3회",
  "difficulty": "상",
  "question": "문제 본문",
  "choices": ["보기1", "보기2", "보기3", "보기4"],
  "answer": 2,
  "explanation": "기본 해설",
  "keywords": ["키워드1", "키워드2"],
  "law_refs": ["L19"]
}
```

- **id**: `S{과목번호}-R{회차번호}-{번호 두 자리}`. 번호는 같은 과목 안에서 회차와 관계없이 이어진다(기존 최댓값 + 1). 기존 ID와 겹치면 안 된다.
- **unit**: 해당 과목의 기존 단원 이름을 글자 그대로 쓴다. 새 단원이 꼭 필요하면 이유를 보고하고, 그 단원을 `units`에 포함하는 법령 조항을 `laws.json`에 함께 추가한다.
- **answer**: 1부터 시작하는 보기 번호.
- **law_refs**: `laws.json`에 실제로 있는 id만 쓴다.

## 4. 검증 가이드라인 (반드시 지킬 것)

### 4.1 내용 정확성
- 법령 수치·기준은 **현행 법령**과 일치해야 한다. `laws.json`에 없는 수치를 쓰려면 법제처 원문(국가법령정보센터 별표·개정령 PDF 등)으로 확인한다. 확인하지 못하면 그 문항을 만들지 않는다.
- 조문 번호는 **확인한 경우에만** 해설에 쓴다. 기억에 의존한 조문 번호를 넣지 않는다.
- 최근 개정된 기준은 개정 후 값을 쓴다. 예: 안전밸브 검사주기 2년·3년·4년, 고정식 사다리 90도.
- 법령이 아닌 교재 기준값(통전전류 범위 등)은 해설에 "교재 기준"임을 밝히고, 교재마다 값이 다른 범위는 정답으로 묻지 않는다.
- 계산 문제는 직접 다시 계산해 정답을 검증하고, 해설에 공식과 대입 과정을 한 줄씩 쓴다.

### 4.2 독창성·중복
- 실제 기출 원문을 옮기지 않는다. 학습용 예시 문제로 직접 작성한다.
- 같은 과목의 기존 문항과 **같은 개념을 같은 방식으로 묻는 문항은 만들지 않는다.** 같은 기준이라도 다른 수치나 다른 측면을 묻는다.

### 4.3 보기와 정답
- 보기는 정확히 4개이고 서로 달라야 한다.
- 오답 보기는 실제로 헷갈리는 값으로 만든다. 예: 다른 조건의 기준값, 단위 환산 누락, 비슷한 용어.
- 숫자 보기는 오름차순으로 배치한다.
- **정답 번호를 고르게 분포시킨다.** 추가한 뒤 전체 정답 위치(①~④) 분포의 최댓값과 최솟값 차이가 4 이하여야 한다(`tests/test_core.py::test_answer_positions_are_balanced`). 문항을 만들기 전에 현재 분포를 확인하고, 적은 번호에 정답을 배치한다.
- "옳지 않은 것은?"처럼 부정형으로 물을 때는 문제 본문에 그 사실을 분명히 쓴다.

### 4.4 난이도 기준
| 난이도 | 기준 |
|---|---|
| 하 | 정의·용어·단순 암기 |
| 중 | 수치 기준, 비슷한 개념 구분, 조건별 값 |
| 상 | 계산, 단위 환산, 두 개념 이상 결합 |

### 4.5 해설·표기
- 해설은 정답 근거와 함께 **주요 오답이 왜 틀렸는지**를 설명한다.
- 해설과 키워드에 "①번", "보기 3" 같은 **보기 번호를 쓰지 않는다.** 보기 섞기를 켜면 번호가 바뀌기 때문이다. 보기 내용으로 가리킨다.
- `$` 기호를 쓰지 않는다(마크다운 수식으로 해석됨). 범위는 `10~15mA`처럼 써도 된다(화면에서 이스케이프됨).
- `keywords`는 2~4개로 하고, 같은 단원의 기존 문항·법령 키워드와 표기를 맞춘다. 유사 문제 추천과 법령 검색이 키워드 일치로 동작한다.

## 5. 추가 방법

- 기존 문항은 **수정하거나 순서를 바꾸지 않고** 파일 끝에 덧붙인다.
- Python으로 JSON을 읽어 덧붙이고 `json.dump(..., ensure_ascii=False, indent=2)` 뒤 줄바꿈 하나로 저장한다(기존 파일 형식 유지).
- 새 법령 조항이 필요하면 `laws.json`에 다음 번호(`L33` …)로 추가한다. `source`에는 확인한 법령명·조문·개정일을 쓴다.

## 6. 추가 후 검증

모두 통과해야 완료다. 실패하면 원인을 고치고 다시 실행한다.

1. `python -m pytest -q` — 데이터 무결성(필드, 정답 범위, 과목명, law_refs), 정답 위치 분포를 포함한 전체 테스트
2. 아래 점검을 실행해 결과를 보고한다.
   ```bash
   python -c "import json,collections; q=json.load(open('data/questions.json',encoding='utf-8')); print(len(q), len({x['id'] for x in q})); print(sorted(collections.Counter(x['answer'] for x in q).items()))"
   ```
3. 새 문항마다 `core.law_search.search(문항)`의 1순위가 의도한 조항인지 확인한다.
